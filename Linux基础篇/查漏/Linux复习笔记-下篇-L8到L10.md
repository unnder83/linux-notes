## L8 压缩传输与定时任务

### 8.1 tar：打包 ≠ 压缩

tar 只负责"打包"（多文件合成一个归档），压缩是 gzip 等工具，tar 顺手调用它们。

```bash
tar -czvf 备份.tar.gz 目录    # c=创建打包, z=gzip压缩, v=显示过程, f=文件名
tar -tzvf 备份.tar.gz         # t=查看归档内容（不解压）
tar -xzvf 备份.tar.gz         # x=解压
tar -xzvf 备份.tar.gz -C 目标目录   # -C 解压到指定目录
tar -cjvf 备份.tar.bz2 目录   # j=bzip2（更高压缩比，更慢）
tar -cJvf 备份.tar.xz 目录    # J=xz（最高压缩比）
```

记忆：**c**reate 打包、e**x**tract 解压、lis**t** 查看；`-f` 后必须跟文件名。

### 8.2 文件传输：scp vs rsync

```bash
scp 本地文件 用户@服务器:/远程路径       # 整体拷贝（基于 SSH）
scp -r 本地目录 用户@服务器:/远程路径    # -r 递归
scp -C 文件 用户@服务器:/路径           # -C 传输时压缩

rsync -avz 源/ 目标/                   # 增量同步（-a 归档 -v 详细 -z 压缩）
rsync -avz --delete 源/ 目标/          # --delete 目标多余文件也删（镜像同步）
```

| | scp | rsync |
|---|---|---|
| 机制 | 整体拷贝 | 增量同步（只传差异） |
| 断点续传 | ❌ | ✅ |
| 压缩 | `-C` | `-z` |
| 适用 | 传单个文件 | 同步目录/备份/部署 |

**末尾斜杠的坑**：
- `rsync -avz 源/ 目标/`（有斜杠）= 拷贝**内容**（源里的东西直接进目标）
- `rsync -avz 源 目标`（无斜杠）= 拷贝**目录本身**（生成 目标/源 目录）

### 8.3 crontab：定时任务

```bash
crontab -e    # 编辑（进入编辑器）
crontab -l    # 查看
crontab -r    # 删除 ⚠️ 清空所有任务，无确认
```

格式（5 个时间字段 + 命令）：
```
分 时 日 月 周  命令
*  *  *  *  *  command

*/5 * * * *     每 5 分钟
0   3 * * *     每天凌晨 3 点
0   0 * * 1     每周一 0 点
@reboot         开机执行
```

---

### 🕳 L8 踩过的坑

1. **crontab 的 PATH 和登录 shell 不同**：cron 环境很干净（通常只有 /usr/bin:/bin），你平时能跑的命令进了 cron 可能"找不到命令"。→ **cron 里一律用绝对路径**（`/usr/bin/date` 而不是 `date`）。
2. **crontab 语法错一个就静默不执行**（不报错）。→ 上线前测试，并验证它真的在跑（看输出日志）。
3. **`crontab -r` 无确认清空所有任务**。
4. **rsync 末尾斜杠没亲手验证**：有斜杠=内容，无斜杠=目录本身，两种都跑一遍对比 `ls` 才能记住。
5. **tar 解压炸弹**：恶意/意外 tar 包解压出巨量文件或 `../` 路径穿越覆盖系统文件。→ 先 `tar -t` 查看再 `tar -x`。

## L9 系统状态、包管理与故障三板斧

### 9.1 系统体检三件套

```bash
uptime      # 运行时长 + load average
free -h     # 内存（RAM + swap）
lscpu       # CPU 信息（核数）
nproc       # 只看核数
```

**load average（负载）是核心概念**：
- 负载 = 正在运行 + 等待运行的进程数
- **要和 CPU 核数比**，不是看绝对数字
- 三个值 = 1 分钟 / 5 分钟 / 15 分钟平均负载

**读负载两步**：① 和 `nproc` 核数比 ② 看三个值趋势
- 1min < 5min → 负载在下降（高峰已过）
- 1min > 5min → 负载在上升（正在恶化）
- 三个都 > 核数 → 持续过载，要动手
- 三个都 ≈ 0 → 空闲

**free -h 的经典误区**：`free` 列看着小是正常的（Linux 把空闲内存拿去做磁盘缓存 buff/cache）。**判断内存够不够看 `available`**，不是 `free`。

### 9.2 包管理：apt 与 dpkg

```bash
sudo apt update              # 更新软件源列表（不是升级软件！）
sudo apt upgrade             # 升级已装软件
sudo apt install 包名        # 安装
sudo apt remove 包名         # 卸载（留配置）
sudo apt purge 包名          # 卸载（连配置一起删）
apt list --upgradable        # 看有多少可升级（仅查看）
apt search 关键字            # 搜包
dpkg -l | grep 关键字        # 看装了什么包
dpkg -L 包名                 # 看这个包装了哪些文件
```

- **apt 和 dpkg 关系**：dpkg 是底层（只管装卸、不解决依赖），apt 是高层封装（自动处理依赖、自动下包）。平时用 apt。

### 9.3 故障三板斧

```bash
dmesg | tail         # 内核日志（硬件/驱动/内核错误）
dmesg -T | tail      # -T 转成可读时间戳
lsof -i              # 谁占端口
lsof -i :80          # 谁占 80 端口
lsof +L1             # 已删除但仍被占用的文件
strace -p PID        # 追踪进程的系统调用（看它卡在哪）
strace -c 命令       # 统计某命令用了哪些系统调用（汇总）
```

| 工具 | 使用时机 |
|---|---|
| dmesg | 怀疑硬件/内核问题：磁盘 IO 错误、内存错误、进程被 OOM 杀掉 |
| lsof | 端口被占、文件被锁、幽灵文件 |
| strace | 服务"卡住不响应"但进程没死——追踪卡在哪个系统调用 |

**strace 风险**：拦截每个系统调用，把被追踪进程拖慢 10~100 倍。→ 只对问题进程、短时间（几十秒 Ctrl+C）、先 `strace -c` 看汇总。

---

### 🕳 L9 踩过的坑

1. **load 趋势读错、结论下早**：4 核机器 load 4.0/8.2/6.5 → 峰值（8.2）已过、正在恢复，应"观察"而非"立即介入"。
2. **"free 列小 = 内存不足"误判**：free 小是因为内存拿去做缓存了，看 available。
3. **strace 和 lsof 搞混**：`lsof -p PID`（列打开的文件，静态）≠ `strace -p PID`（追踪系统调用，动态）。口诀：strace 动态监控，lsof 静态快照。
4. **strace 风险答成"输出太多"**：真正的风险是"拖慢被追踪的进程"。
5. **strace 需要 sudo**：`strace -p PID` 报 `Operation not permitted`（ptrace_scope 限制），加 `sudo`。

## L10 Shell 脚本 + SSH 免密

### 10.1 脚本基础

- 第一行 `#!/bin/bash`（shebang，指定解释器）
- `chmod +x 脚本` 加执行权限，`./脚本` 执行

### 10.2 变量与参数

```bash
name="world"       # 赋值：= 两边绝对不能有空格！
echo $name         # 取值
echo ${name}       # 严格写法（防止粘连）

# 特殊变量
$0    # 脚本名
$1    # 第 1 个参数
$#    # 参数个数
$?    # 上一条命令退出码（0=成功，非 0=失败）
$(命令)  # 命令替换（老朋友了）
${1:-默认值}  # 参数默认值：$1 为空就用默认值
```

### 10.3 条件判断 if

```bash
if [ -d "$dir" ]; then    # [ 和 ] 内侧必须有空格！
    条件成立
else
    条件不成立
fi
```

常用测试：
```bash
[ -f 文件 ]      # 是普通文件
[ -d 目录 ]      # 是目录
[ -e 路径 ]      # 存在（文件或目录）
[ "$a" = "$b" ]  # 字符串相等
[ "$a" != "$b" ] # 字符串不等
[ -z "$s" ]      # 字符串为空
[ $n -gt 10 ]    # 数字大于（-lt 小于 -eq 等于 -ge 大于等于）
```

### 10.4 循环

```bash
for i in $(seq 1 5); do
    echo "第 $i 次"
done

for item in "$dir"/*; do    # 遍历目录下所有项
    ...
done

while [ 条件 ]; do
    ...
done
```

### 10.5 逻辑连接 + 脚本健壮性

```bash
mkdir /tmp/x && echo "成功" || echo "失败"   # && 成功才执行后，|| 失败才执行后

set -euo pipefail   # 生产脚本开头标配
# -e：任一命令失败立即退出
# -u：用了未定义变量就报错
# -o pipefail：管道里任一命令失败，整个管道算失败
```

### 10.6 read 交互

```bash
read -p "确认删除？(y/N) " answer    # 打印提示 + 读入用户输入存进 answer
```

### 10.7 SSH 免密

```bash
ssh-keygen -t ed25519 -f ~/.ssh/id_ed25519   # 生成密钥对（一路回车=无密码短语）
ls -l ~/.ssh/                                # id_ed25519（私钥）+ .pub（公钥）
chmod 600 ~/.ssh/id_ed25519                  # 私钥权限必须 600
cat ~/.ssh/id_ed25519.pub                    # 看公钥
ssh-copy-id 用户@服务器                       # 把公钥装到对方机器
ssh 用户@服务器                               # 验证免密登录
```

**原理**：非对称加密。私钥自己留，公钥发给服务器。登录时你拿私钥签名，服务器用公钥验签，匹配放行——全程不输密码。

### 🕳 L10 踩过的坑

1. **赋值 `name = "x"` 有空格 → 报错**：`=` 两边不能有空格。
2. **`[ $a = $b ]` 没空格 → 报错**：`[ ]` 内侧必须有空格。
3. **脚本名 `gree.sh` 少字母**：规范命名。
4. **`$(date)` 和 `$(date +%F)` 区别**：前者日期+时间，后者只要日期（`+%F` 控制格式）。
5. **`echo $?` 验证退出码（三次漏掉）**：脚本跑完必须验证退出码，尤其错误分支是否真返回了非 0。生产脚本靠退出码判断成败。
6. **`-d` / `-e` / `-f` 混用**：`-d`=是目录，`-e`=存在，`-f`=是普通文件。
7. **for 循环 `continue` 跳过的是 `.` 和 `..`**（当前/上级目录的特殊项），不是"隐藏文件"。`.*` 匹配到的隐藏文件是要计数的。
8. **会删文件的脚本命名成 `preview.sh`**：脚本名要如实反映行为，删除类叫 `clean-log.sh`，否则有副作用误执行风险。
9. **私钥权限必须 600**、绝不上传 git/聊天群。
10. **脚本放 cron 里用绝对路径**（L8 的 PATH 坑）。

## 全课程通用铁律（最后再背一遍）

1. 改任何配置文件前先 `cp` 备份，改完 `diff` 验证
2. 删任何东西前先 `ls` 看清楚，再想 3 秒
3. 最小权限原则，永远不用 777
4. 先看日志找根因，再动手，别盲目重启/杀进程
5. 脚本跑完验证退出码 `echo $?`
6. 命令敲完看 `ls`（防止重定向写错目标产生意外文件）
7. 作业/记录提交前 `cat` 检查一遍
