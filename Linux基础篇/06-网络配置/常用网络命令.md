# 常用网络命令

### 1. 网络排查的核心思想：按"链路分段"定位

网络从"服务"到"用户"之间是一段一段的，排查就是**从内往外逐段排查**，定位问题卡在哪一段：

```textile
① 服务进程       ② 本机端口       ③ 防火墙       ④ 本机到目标       ⑤ 目标服务
  (起了吗)   →   (监听了吗)   →   (放行了吗)   →   (网络通吗)    →   (对方起了吗)
  ps/status     ss -tlnp        iptables/ufw   ping/ip route    telnet/curl

```

**端口不通的经典四段式**

1. **服务监听了吗**：`ss -tlnp | grep 端口`
2. **本机自己通吗**：`curl 127.0.0.1:端口` 或 `telnet 127.0.0.1 端口`
3. **防火墙挡了吗**：`sudo ufw status` / `sudo iptables -L -n`
4. **外部通吗**：从另一台机器 `telnet IP 端口`

### 2. 核心命令

```bash
ip addr                    # 看网卡 IP、状态（UP/DOWN）—— 替代老命令 ifconfig
ip route                   # 看路由表，找默认网关（default via ...）
ping -c 4 网关IP           # ICMP 测连通（-c 限制次数，否则一直 ping）
ss -tlnp                   # 看本机监听的 TCP 端口和进程（替代 netstat）
telnet IP 端口 / nc -zv IP 端口   # 测远程端口通不通
curl -I http://IP:端口      # HTTP 层面测试
sudo iptables -L -n        # 看防火墙规则
```

### 3.坑点

- ⚠️ **`ping` 不通 ≠ 服务不通**：很多服务器直接禁 ICMP（防扫描），ping 不通但服务好好的。所以排障别把 ping 当唯一标准。
- ⚠️ **`0.0.0.0:22` 和 `127.0.0.1:22` 天壤之别**：
  - `0.0.0.0` = 监听所有网卡，**全网可访问**
  - `127.0.0.1` = 只监听本机回环，**只有本机能访问**，外部进不来
  - 很多"外部访问不了"的故障，就是服务只听在 127.0.0.1 上
- ⚠️ **`ss` 里看不到端口 = 服务根本没监听**（没起 / 配置错 / 监听地址错），这是第一段要确认的事

### 4. 生产坑点

- ⚠️ **iptables 规则是顺序匹配**，第一条命中的规则生效，后面的不看——加规则时顺序错了会"看似加了但没生效"
- ⚠️ **远程改防火墙 = 高危**：一条规则写错可能把自己 SSH 连接锁死，改之前先记录现有规则、留后路
- ⚠️ `nc`/`telnet` 是排障神器，但别在生产机器上乱扫端口，可能触发安全告警
