## 磁盘结构

```textile
物理磁盘 /dev/sda
   └─ 分区 /dev/sda1、/dev/sda2 ...
         └─ 格式化（建文件系统 ext4/xfs）
               └─ 挂载（mount）到目录树的某个点，如 / 或 /home
```

## 常用命令

```bash
df -h                          # 文件系统整体用量（容量/已用/可用/挂载点）
du -sh 目录                    # 某目录总共占多大
du -h --max-depth=1 / | sort -rh | head   # 分层找大目录
lsblk                          # 看块设备层级（磁盘/分区/挂载点）
sudo fdisk -l                  # 看磁盘分区表
mount                          # 看当前所有挂载情况
df -i                          # 看 inode 用量（不是空间，是"文件数量"）
```

### 常用参数

```bash
df -h    #-h:人类可读
du -h    #-h:人类可读
   -s    #指定目录占用大小汇总
   -a    #带文件
   -c    #列出明细并增加汇总值
   --max-depth=1    #子目录深度
```

## 经典问题

**① df 和 du 对不上**：`df` 显示已用 10G，但 `du` 把所有目录加起来只有 6G。原因通常是——**有"幽灵文件"**：文件被 `rm` 了，但还有进程占着它的 inode（L1 的 unlink！）。`df` 按文件系统算（空间真没释放），`du` 按目录遍历（名字没了，遍历不到）。

**② 空间够但建不了文件**：`df -h` 显示还有空间，却报"磁盘满"。原因是 **inode 耗尽**——文件系统里的 inode 数量有限，几百万个小文件会耗尽 inode。用 `df -i` 能看到 inode 使用率 100%。

## 坑

- ⚠️ `/var/log`、`/tmp`、`/` 被写满是最高频故障（日志不轮转、临时文件堆积）
- ⚠️ **删日志文件 ≠ 释放空间**（幽灵文件），正确做法是清空 `> file` 或 logrotate
- ⚠️ **挂载点遮挡**：某目录下新挂载了磁盘，原来目录里的旧文件被"遮住"——你 `du` 不到它们，但它们还在占空间
- ⚠️ 磁盘满会导致服务无法写日志、数据库无法写入，**连锁反应**，所以要早发现
